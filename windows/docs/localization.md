# Windows 현지화

현지화는 문장을 다른 언어로 바꾸는 일만 뜻하지 않아요. 사용자가 선택한 앱 언어로 문구와 숫자를 보여 주면서, 날짜와 시각은 사용자의 Windows 지역과 시간대에 맞게 해석되도록 만드는 일이에요.

## 지원 언어를 한곳에서 예상할 수 있어야 해요

Windows 클라이언트는 다음 BCP 47 언어 태그를 지원해요.

| 태그 | 언어 |
| --- | --- |
| `bg-BG` | 불가리아어 |
| `cs-CZ` | 체코어 |
| `de-DE` | 독일어 |
| `en-US` | 영어 |
| `es-ES` | 스페인어 |
| `fr-FR` | 프랑스어 |
| `he-IL` | 히브리어 |
| `it-IT` | 이탈리아어 |
| `ja-JP` | 일본어 |
| `ko-KR` | 한국어 |
| `nl-BE` | 네덜란드어(벨기에) |
| `nl-NL` | 네덜란드어(네덜란드) |
| `pl-PL` | 폴란드어 |
| `pt-BR` | 포르투갈어(브라질) |
| `pt-PT` | 포르투갈어(포르투갈) |
| `ro-RO` | 루마니아어 |

기본 언어는 `ko-KR`이에요. 지원 목록은 `I18n.SupportedLanguages`가 소유하고, 실행 중에는 `SIDEY_LANGUAGE` 환경 변수를 통해 선택한 언어를 전달해요.
히브리어를 선택하면 WinUI 화면의 읽기 방향도 오른쪽에서 왼쪽으로 바뀌어요. 설치 프로그램의 언어 목록은 앱 카탈로그와 별도로 관리하므로, 설치 프로그램이 지원하지 않는 언어도 설치 후 앱 설정에서 선택할 수 있어요.

## 사용자 문구는 카탈로그에서 읽어요

번역 파일은 `src/Sidey.App/Langs/<언어 태그>.json`에 있어요. 중첩된 JSON 키는 점으로 이어진 하나의 키로 읽어요.

```json
{
  "connection": {
    "retry": "다시 연결"
  }
}
```

```csharp
string label = I18n.Get("connection.retry");
```

코드에 사용자 문구를 직접 넣으면 새 언어를 추가할 때 검색으로 빠진 문구를 찾아야 해요. 카탈로그 키를 사용하면 모든 언어가 같은 구조를 갖는지 자동으로 검사할 수 있어요.

값을 끼워 넣는 문장은 `I18n.Format()`을 사용해요.

```json
{
  "room": {
    "memberCount": "{0}명"
  }
}
```

```csharp
string text = I18n.Format("room.memberCount", memberCount);
```

번역마다 어순이 다르므로 문장을 여러 키로 잘게 이어 붙이지 않아요. 완성된 문장 하나를 번역 단위로 두고 자리표시자를 사용해요.

## 키는 동작이 아니라 의미를 나타내요

`button1`이나 `blueText`는 화면 배치가 바뀌면 의미를 잃어요. `connection.retry`처럼 사용자가 보게 될 의미와 맥락을 이름에 담아요.

- 같은 뜻과 같은 맥락이면 기존 키를 재사용해요.
- 같은 한국어라도 맥락이 다르면 키를 나눠요.
- 키 이름에 특정 언어나 현재 화면 위치를 넣지 않아요.
- 접근성 이름과 오류 안내도 사용자 문구이므로 카탈로그에서 관리해요.

## 모든 언어의 계약을 함께 바꿔요

새 키를 한 파일에만 추가하면 선택한 언어에 따라 빈 문구나 키 이름이 화면에 나타날 수 있어요. `LanguageCatalogParityTests`는 다음 계약을 확인해요.

- 모든 카탈로그가 같은 키를 갖는가
- 값이 비어 있지 않은가
- 자리표시자 번호가 기준 언어와 같은가
- 한국어가 아닌 카탈로그에 한국어 문구가 남아 있지 않은가

새 문구를 추가할 때는 모든 지원 언어 파일을 한 변경에서 갱신하고 이 테스트를 실행해요. 번역이 확정되지 않았다고 한국어 원문을 다른 언어 파일에 복사하지 않아요. 정확한 번역을 준비하거나 기능 변경을 보류해요.

## 날짜와 숫자는 서로 다른 기준을 따라요

날짜와 시각은 사용자의 시스템 로캘과 시간대를 따라요. 같은 순간도 사용자가 사는 곳에 따라 날짜가 달라질 수 있기 때문이에요. 서버와 로그에서는 UTC를 유지하고, 화면에 보여 줄 때만 지역 시간으로 바꿔요.

앱 안의 일반 숫자와 번역 형식은 선택한 앱 언어를 따라요. 정렬이나 프로토콜 값처럼 기계가 읽는 데이터에는 고정 문화권 또는 명시적인 형식을 사용해요.

## 새 언어는 JSON 파일 하나로 끝나지 않아요

언어를 추가하면 다음 위치가 같은 태그를 이해하는지 확인해요.

1. `I18n.SupportedLanguages`와 기본 선택 규칙
2. `Langs/<태그>.json`
3. 런처의 언어 전달과 매핑
4. 설치 관리자의 지원 언어도 늘리는 변경이라면 언어 선택 화면과 안내 문구
5. 빌드·게시 결과에 카탈로그가 포함되는 규칙
6. `LanguageCatalogParityTests`와 배포 검사

앱 카탈로그와 런처, 게시 규칙 중 한 위치라도 빠지면 선택한 언어가 적용되지 않거나 게시본에서 카탈로그를 찾지 못해요. 설치 프로그램의 언어도 함께 추가할 때는 설치 관리자 계약과 테스트까지 같은 변경에서 맞춰야 해요.

## 확인 순서

자동 테스트를 통과한 뒤 실제 앱에서 다음을 확인해요.

- 첫 실행, 메인 창, 작성 창, 기록 창, 설정, 알림 영역 문구
- 긴 번역이 잘리거나 버튼을 밀어내지 않는지
- 자리표시자가 그대로 보이지 않는지
- 앱을 다시 시작해도 선택한 언어가 유지되는지
- 설치 관리자가 선택한 언어가 첫 실행에 전달되는지
- 날짜와 시각이 Windows 지역과 시간대에 맞는지
